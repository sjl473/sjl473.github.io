v0plex: A Next.js Theme Copied From IBM Carbon Design

v0plex是使用Next.js和IBM Plex系列字体，仿照IBM Carbon Design System而设计的博客页面。

我不是 IBM 的员工也不是前端专家，但在一开始我就发现了 Carbon Design 相交其他 Design System 的优势，于是我坚定选择必须要用这个framework，否则我就不打算写个人网站，为什么这么执着呢？原因如下。

从扁平化、组件化 ui 流行开始，比如 bootstrap，设计者更多的追求的是 colorful 和响应式布局，比如从原始的 html css 设计元素上以颜色和边框和填充，作为页面元素的观感增强。互联网的起飞也使得同一套 web 页面要适配桌面设备和移动设备。而从 iphone, google material ui 开始，设计者更多的是追求元素动作的连续，这也影响了移动端应用的设计。在 react 和 vue 流行后，很多互联网企业开源了自己的 design system 并以 jsx 和 vue 封装，比如 ant-design 和 element-ui。这两种代表性的 ui 也广泛的应用与多个大中小企业的复杂应用，很好的经过了实践的检验。

作为更新速度远远超过后端的前端，各种数不清的 js 技术栈三个月就会更新一番。用户作为使用者并不在意这些底层的实现，他们更在乎产品自身的表达。过多的前端开发框架也让一部分的开发者感到审美疲劳。比起技术自身的审美疲劳，用户更加感觉审美疲劳的是产品本身。过多的 design system 并没有新的设计思路，而是各种白色蓝色按钮和毫无章法的排版，不断的换一个壳子重复自己，甚至不论在地球的哪一家公司，这更加讽刺的凸显了信息时代的干瘪化、无趣化。

如何强化一个产品的表达，从 component design 的层面，频繁更新的意义已经不大，component design 的更新早就已经达到了摩尔定律极限, 新时代产品的表达应该更抓住重点。

从古代人类做出壁画开始，他们就要考虑在哪表达的问题。如果一块巨大的岩石摆在你面前，你更希望在中间画还是在左上画呢？从心理学上讲，在哪画是一种心理暗示。人从左上开始和从中间开始作画的意义是不一样的，画的幅度占据了整个篇幅和占据一个小角落又是不一样的。这一切的一切都属于 layout，既不属于 component，也不属于 ui，也不属于 typography。layout 的问题是一个视觉观感的问题，本质上是潜意识问题。

IBM 的 Carbon Design 在 Grid（网格）、Motion（动效）、Typography（排版）这三个层面有强硬的规范，这正是其核心优势。例如，它的 Grid 系统不仅定义列宽，更严格规定了内容如何精确对齐网格线，包括文字基线、元素边缘与网格的关系。Motion 的淡如淡出规定了每个动画的时长、缓动曲线都有明确指引。Typography 则对字体层级、行高、字距甚至不同场景下的文本长度都有细致入微的规则。相比之下，许多流行的系统（如 Ant Design 或 Element UI）在这些方面的规定显得松散甚至缺失。它们可能提供了基本的网格工具，但缺乏对元素在网格中精确定位的强制要求，页面的整体不够 concentrate。

对Layout的严格是我最欣赏的一点，大部分的 design language 虽然有规定 grid，但只是对页面宽度机械性的划分，并没有规定文字的上宽度下宽度必须应该和哪个 grid 的边角做到精确对齐，这就像是高级设计者对低级设计者的碾压，因为高级设计者知道鹦鹉螺的螺旋线是遵循某种数学公式的，江河、闪电、树木也只是流形的一种三维呈现。而低级设计者的设计从不遵循某种原则，并有一种又不是不能用的侥幸心理。

作为一个非前端开发者，规范自己的 grid 和 space 并让元素机械性地对齐是一种设计也是自我表达。这种自我表达并非是一种死板，而是在一众平平的 product 中让自我脱颖而出的一种手段，即使所谓 product 只是一个小博客。这就是 IBM Carbon Design 对我的启发。
